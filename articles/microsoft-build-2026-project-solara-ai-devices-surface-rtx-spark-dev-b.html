Microsoft's Build 2026 developer conference ran June 2–3 at Fort Mason Center in San Francisco, and Satya Nadella's opening keynote — which ran for a full two and a half hours — contained more consequential announcements than many previous Build events combined. The central thesis was deliberate and repeated: the era of discrete applications that do one thing per launch is ending, and the era of AI agents that work autonomously on your behalf — across every app, file, inbox, and system — is beginning. Everything Microsoft announced at Build 2026 pointed toward that single, enormous bet.

This is a full breakdown of every major announcement, explained plainly — what was launched, what it actually does, why it matters, and where it fits in Microsoft's broader strategy. No jargon left unexplained. No announcements omitted to make the narrative cleaner. Build 2026 produced a genuine firehose of news, and understanding it fully requires covering all of it.

The Big Picture: Windows Becomes the Operating System for AI Agents

Nadella opened the keynote not with a product announcement but with a framing statement that set the tone for everything that followed. He pointed to the amount of local compute already sitting inside modern PCs — already doing real work in Outlook summaries, PowerPoint alt-text generation, Teams super-resolution, and Adobe tools — and argued that developers have been dramatically underestimating what that compute can do. His argument: Windows should become the development and deployment environment for the agent era, not just a platform for running apps.

The logic behind that framing explains the breadth of Build 2026's announcements. Windows AI APIs are being expanded to reach more Windows 11 PCs across CPU, GPU, and NPU configurations. A new speech-to-text recognition API is available on NPUs and CPUs. An on-device SLM now expands to capable discrete GPUs, enabling text-intelligence features locally. Video Super Resolution is available on CPUs so developers can deliver richer experiences without a cloud round trip. None of these announcements made individual headlines. Collectively, they describe a platform strategy: Microsoft wants Windows to be a place where agents can run, be tested, governed, and deployed — before they ever touch the cloud.

The parallel enterprise play is Microsoft Agent 365, which reached general availability on May 1, 2026, and forms the enterprise control plane for deploying, governing, and managing AI agents at corporate scale. Build built on that foundation with the Agent 365 SDK, Local Agents support, and Microsoft Entra Agent ID — a system that gives every AI agent its own verifiable identity, the same way employees have login credentials. That last detail is quietly important: it means IT departments can audit exactly which agent did what, at what time, under whose authority.

Surface RTX Spark Dev Box & NVIDIA DGX Station — Local AI at Desktop Scale

The most tangible hardware announcement of Build 2026 is the Surface RTX Spark Dev Box — a compact desktop developer PC built around NVIDIA's RTX Spark silicon, which Microsoft and NVIDIA had already announced at Computex earlier in the week. The device delivers up to 1 petaflop of AI compute with 128GB of unified memory. The headline capability is running AI models of up to 120 billion parameters entirely locally — no cloud subscription, no API costs, no data leaving the building.

To appreciate why that matters, consider the context: until now, running a frontier-class AI model locally required either expensive cloud GPU access or research-grade hardware that costs six figures. The Surface RTX Spark Dev Box changes that calculus for professional developers. A 120-billion-parameter model can now sit on a desk in an office. Nadella called it a "dream machine" from the stage and said he had personally joined the waitlist to buy one — not a common move for a CEO to volunteer unprompted, and notable for how it signals the device's intended credibility.

Alongside the Dev Box, Microsoft and NVIDIA announced the DGX Station for Windows — described as the world's most powerful deskside AI supercomputer. Where the RTX Spark Dev Box targets individual developers, the DGX Station targets teams working on frontier agent development, model fine-tuning, and large-scale inference. NVIDIA is bringing OpenShell — its own open-source agent runtime, focused on sandboxed execution, policy enforcement, and auditability — to Windows via MXC, creating a unified stack that runs from the developer desktop all the way to Azure-scale cloud infrastructure.

Microsoft Execution Containers (MXC) — The Most Important Announcement You Might Have Missed

If the Surface RTX Spark Dev Box was the flashiest hardware announcement at Build 2026, Microsoft Execution Containers — MXC — may prove to be the most consequential overall. VentureBeat called it "arguably the most consequential platform move Microsoft made at Build this year," and the reasoning holds up.

MXC is not a product you buy. It is a policy-driven execution layer built into the Windows operating system itself and into the Windows Subsystem for Linux (WSL). The way it works: a developer or IT administrator declares what an AI agent is allowed to access before that agent runs. Which files. Which network connections. Which system processes. Which user data. Windows then enforces those constraints at runtime, at the kernel level — not by trusting the agent to stay within bounds, but by making it structurally impossible for the agent to go outside them.

Microsoft describes MXC as providing a "composable sandbox spectrum," meaning the level of isolation is configurable. Process isolation suits short-running coding agent scenarios. Session isolation is designed for longer-running workloads. Micro-VM isolation and Linux container integration are on the roadmap for higher-security environments. Integration with Windows 365 for Agents — which gives computer-using agents secure, managed Cloud PCs to execute enterprise workflows (now generally available) — is also planned.

OpenAI and NVIDIA are both already building on MXC. OpenClaw, the open-source agent runtime with more than 350,000 GitHub stars, is now in alpha on Windows, running inside MXC. NVIDIA OpenShell is integrating with MXC to provide developers with a ready-to-deploy package for autonomous, always-on agents that are genuinely sandboxed. The enterprise pitch is clear: deploy AI agents that your IT department can actually audit, govern, and contain — agents that cannot delete your files, exfiltrate your data, or take actions they were not explicitly authorised to take.

One caveat worth noting: MXC is currently early-preview software. Microsoft's own GitHub repository states that no MXC profiles should currently be treated as hard security boundaries, and some policies remain overly permissive pending further development. The direction is clear and the architecture is sound, but production enterprise deployments should wait for the software to mature.

Project Solara — Computers Without Apps or Operating Systems

Project Solara is Microsoft's most conceptually radical announcement at Build 2026. It is a chip-to-cloud platform for agent-first devices — hardware designed from the beginning to run AI agents rather than a traditional operating system or installed applications. Think of it as the inverse of everything computing has been for the past four decades. No Windows. No Android. No apps to launch, update, or manage. Just agents, connected to cloud infrastructure, performing specific tasks.

The form factors shown at Build were deliberately practical. A desk-based unit approximately the size of a small smart speaker, with a screen and microphone, powered by Qualcomm chips. A wearable badge concept, running MediaTek silicon. Both connect to Microsoft's cloud infrastructure and can host AI agents purpose-built for specific environments. A Solara device in a medical office could document patient visits in real time, surface relevant clinical information, and route paperwork automatically. A Solara device at a retail customer service desk could handle inventory queries, process returns, and escalate complex requests — all without requiring a full PC, login credentials, or a Windows licence.

AccuWeather, Best Buy, CVS, Target, and Levi Strauss are among the first organisations publicly exploring Project Solara for specific business applications. The broader message Microsoft is sending with Solara is that the next decade of computing growth — especially in the enterprise — may not come from selling more PCs. It may come from selling purpose-built agent endpoints, deployed in physical spaces where a full computer never made sense before.

Scout & Copilot Autopilots — Your Always-On AI Work Agent

Alongside the platform and hardware announcements, Nadella introduced Copilot Autopilots — a category of long-running autonomous agents designed to work on your behalf continuously, not just when prompted. The first Autopilot is called Scout, and it is the clearest demonstration of what Microsoft means when it talks about replacing app-based workflows with agent-driven ones.

Scout is an always-on work agent built on OpenClaw, running inside MXC, with its own Microsoft Entra identity for governance and audit. It operates across Teams, Outlook, OneDrive, SharePoint, and local device actions simultaneously — reading your incoming messages, emails, and notifications, identifying items that require a decision or response, and surfacing them proactively. The demo showed Scout identifying a supplier negotiation thread that had been waiting in an inbox for several days, flagging a budget approval buried in a SharePoint comment, and routing a Teams message that needed a specific expert's attention — all without the user having to search, scroll, or click through application menus.

The key architectural detail of Scout and all Autopilots is the Entra identity: every action the agent takes is logged under its own identity, creating an audit trail that enterprise compliance and IT teams can review. The agent is not invisible. It is a governed participant in the organisation's information systems, with defined permissions and a record of everything it does. That governance layer is what separates Autopilots from the consumer AI assistants that enterprises have been hesitant to adopt — and it is built into the foundation, not bolted on afterward.

Seven MAI Models — Microsoft's Clean Break From OpenAI

Mustafa Suleyman, CEO of Microsoft AI, took the stage to announce seven new AI models under the MAI brand — and to make a point that was as much strategic as technical. Every single MAI model, he said, was trained from scratch using clean, commercially licensed data. No OpenAI models were used. No data of uncertain provenance or licensing. "We train from scratch. We don't distill from other labs and we don't rely on unlicensed or opaque data," Suleyman said from the stage. "Our datasets are clean and appropriately licensed. Every component of the system, from architecture to training pipeline to post-training, we built ourselves."

That statement matters commercially as much as technically. Enterprise customers using MAI models in regulated industries can point to a clean provenance chain with no dependency on a third-party lab's training decisions. For organisations that are genuinely concerned about AI training data provenance — a growing category of enterprise buyer — it is a meaningful differentiator.

The broader ambition Suleyman articulated is what he called "humanist superintelligence" — AI that places humans first and supports workers rather than replacing them. Aion Local Models & GitHub Copilot App

On the local model front, Microsoft introduced two new on-device small language models — SLMs — designed to run fully on Windows hardware without any cloud connection. Aion 1.0 Instruct is described as smaller, faster, and smarter than its predecessors, targeting quick on-device inference. Aion 1.0 Plan is specifically designed as a reasoning and tool-calling model for local agent workflows — the critical capability that allows an agent to decide what action to take next, call external tools, and plan multi-step tasks, all without leaving the device. Both are available in the coming months, and both are critical to the Windows-as-agent-platform vision: you cannot build a serious local agent workflow without a capable local planning model.

For developers, the GitHub Copilot App landed as a significant practical upgrade. Now available in preview, it brings agentic workflows to a native desktop experience for the first time. Previously, GitHub Copilot operated primarily within IDEs and the browser. The desktop app allows developers to kick off agentic coding tasks — multi-file edits, test generation, documentation runs — and have them execute in the background while other work continues. MAI-Code-1-Flash is rolling out to all GitHub Copilot subscription tiers simultaneously, meaning Free plan users get access to the same underlying model as Pro and Pro+ subscribers.

Visual Studio also received agent-focused upgrades at Build: GitHub Copilot in Visual Studio is moving beyond chat and completion suggestions toward agents that participate actively in debugging, profiling, and testing workflows. The framing from Microsoft's developer blog is that code should be treated as an asset to keep healthy and correct as it evolves, not just an artifact of a particular sprint. Copilot agents in VS are being positioned as contributors to that ongoing code health — debugging alongside you, not just when you ask.

Azure AI Foundry, Azure HorizonDB & Project Rayfin

Azure AI Foundry is the platform layer that ties together Microsoft's model access, agent hosting, and developer tooling across the cloud. At Build 2026, it received several significant updates. Azure AI Foundry can now automatically select the most appropriate model for a given task, removing the need for developers to hard-code model choices into their applications. The platform now hosts both Claude models from Anthropic and OpenAI's GPT-5.5 alongside the MAI family — making it genuinely multi-model and reducing the risk of single-vendor lock-in for enterprise developers.

Microsoft IQ, now generally available across GitHub Copilot, Foundry, and Copilot Studios, provides the context layer that makes agents useful in real enterprise environments. It has three components: Work IQ, which pulls real workplace knowledge from Microsoft 365 signals; Fabric IQ, which provides structured business data access; and Web IQ, which grounds agents in current web information rather than stale training data. Web IQ is particularly notable — it means an agent built on Foundry can answer questions about events that happened yesterday, not just events that appeared in its training corpus.

Frontier Tuning, in private preview, allows enterprises to train agents on their own workflows, documents, and institutional knowledge — within their compliance boundaries, using their own data. The Foundry Toolkit for VS Code is now generally available, allowing developers to create agents from templates, debug runs locally with trace visualisation, and deploy to Foundry agents directly from the IDE.

Azure HorizonDB is Microsoft's new fully managed PostgreSQL-compatible database service engineered specifically for agentic applications. It delivers up to 3x faster transactions and search performance compared to self-managed PostgreSQL, with built-in AI features including advanced vector indexing for semantic search, in-database AI model access, and native integration with Microsoft Fabric and Microsoft Foundry. For developers building memory and retrieval systems for agents — which require high-throughput, low-latency database reads — HorizonDB is designed to remove the infrastructure friction that has made agent memory systems difficult to scale.

Project Rayfin, in preview, addresses the prototype-to-production gap that has long frustrated AI developers. Once a working agent prototype exists, deploying it at scale on reliable infrastructure has typically required significant additional engineering. Rayfin provides a managed backend-as-a-service on Microsoft Fabric with GitHub-defined workflows, allowing teams to move from working prototype to production deployment without rebuilding the underlying infrastructure from scratch.

Microsoft Discovery — AI for Scientific Research (Now GA)

Microsoft Discovery, now generally available with an early-preview app, is an agentic AI platform built specifically for scientific research and development. It deploys specialised agents that work together using knowledge graphs, simulations, and lab workflow automation to help researchers move through the scientific method faster. The system generates hypotheses based on existing research, validates theories against available data in a continuous loop, designs experiments, helps write scientific papers, carries out virtual tasks, and suggests next steps such as creating lab protocols.

The target markets are industries where research cycles are long and costly: pharmaceuticals, energy, food science, and other regulated sectors where each failed experimental run has measurable financial consequences. Microsoft's pitch is that AI can compress years of research iteration into months by automating the hypothesis-test-refine cycle at machine speed, reserving human attention for the scientific judgements that require genuine expertise. The platform does not replace scientists — it removes the administrative and computational overhead from their work, so they can focus on insight rather than data processing.

The Microsoft and Mayo Clinic Healthcare AI Partnership

The most headline-generating announcement of Build 2026 came near the end of Suleyman's segment: a joint partnership between Microsoft AI and Mayo Clinic to co-create a frontier AI model specifically for clinical healthcare. Mayo Clinic CEO Dr. Gianrico Farrugia joined Suleyman on stage to explain the ambition. "Mayo Clinic Platform has spent seven years moving healthcare from a pipeline to a platform," Farrugia said, describing Mayo's existing investment in de-identified clinical data, longitudinal patient records, and proprietary clinical expertise.

The partnership combines that clinical depth with Microsoft's foundational AI capabilities to build a model designed to excel at the broadest scope of clinical reasoning — diagnosis support, treatment planning, differential analysis — at a level that general-purpose AI systems cannot currently match. The model will be owned by Mayo Clinic, not by Microsoft, reinforcing a specific commitment to patient trust and data stewardship that Suleyman described as non-negotiable. It will first be deployed within Mayo Clinic's own hospital environment — the world's top-ranked hospital system — for validation. Once validated, it will be made available to other health organisations via Azure Foundry.

Suleyman was candid about the timeline: this will take "many years" to train and validate to clinical accuracy standards. Both parties declined to disclose the financial commitment involved, but Suleyman confirmed they are making "very material, long-term commitments to one another." For AI vendors competing in healthcare — a sector where regulatory requirements, liability concerns, and data governance demands have slowed adoption — the Mayo Clinic's institutional endorsement is a commercially significant signal, independent of the model's eventual technical performance.

Majorana 2 — Microsoft's Quantum Computer Target for 2029

Nadella closed the Build 2026 keynote by introducing Majorana 2, Microsoft's next-generation quantum computing chip. The original Majorana 1, released in 2025, demonstrated a new topological qubit approach using a state of matter that had previously existed only in theoretical physics. Majorana 2 moves from that physics proof to engineering scale, using lead as a key material in its construction to achieve qubit lifetimes averaging 20 seconds — and what Microsoft claims is a 1,000-times improvement in reliability over Majorana 1.

With Majorana 2, Microsoft says it is now beginning the engineering phase of scaling toward a commercially valuable quantum computer. The target: a scalable quantum machine delivering commercially useful output by 2029. Independent physicists have expressed cautious scepticism about some of the Majorana 2 claims, which are based on an unreviewed preprint rather than peer-reviewed publication — a standard caveat for any leading-edge quantum result. But the engineering trajectory is real, and Microsoft's timeline, if achieved, would place it ahead of most competitors in the race to commercially relevant quantum computation.

Azure Infrastructure: Maia 200, Cobalt 200 & the MRC Protocol

Underpinning everything Microsoft announced at Build 2026 is an infrastructure layer that rarely gets discussed in mainstream tech coverage but that makes the scale of the agent era possible. Maia 200 — Microsoft's in-house AI training chip — is now running in production across Azure data centres, reducing Microsoft's dependence on NVIDIA GPUs for its own AI workloads and giving it more control over training economics. Cobalt 200, Microsoft's custom ARM-based CPU designed for general cloud computing, is in preview, providing cost-optimised compute for the long-tail workloads that surround AI inference.

The Multipath Reliable Connection protocol — MRC — is an open network standard co-developed with AMD, Broadcom, Intel, OpenAI, and NVIDIA. It is designed to keep extreme-scale AI training and inference workloads moving reliably across the network connections inside hyperscale data centres, where a single dropped packet or network fluctuation can cascade into significant compute waste. The co-development coalition is notable: it means MRC is positioned as an industry standard rather than a proprietary Microsoft protocol, which increases the likelihood of broad adoption across cloud providers.

Conclusion — What Microsoft Build 2026 Actually Means

The announcements at Build 2026 are best understood not as a collection of individual products but as components of a single unified bet. Microsoft is arguing that the next major computing transition — from applications that do one thing to agents that do many things autonomously — will be won at the platform level. Not by the company with the best individual AI model. Not by the company with the flashiest consumer product. But by the company whose operating system, cloud infrastructure, developer tools, hardware ecosystem, and enterprise governance layer are all built to work together for an agent-first world.

MXC, Solara, Scout, the MAI model family, Aion, Foundry, HorizonDB, Maia 200, Majorana 2, the Mayo Clinic partnership — these are not separate initiatives. They are the same initiative, expressed at different layers of a computing stack that Microsoft is trying to own end to end. The app era produced decades of reliable business for the company that owned the operating system. If the agent era plays out the way Nadella believes it will, Microsoft's strategy at Build 2026 is designed to ensure the same outcome happens again.

Whether that strategy succeeds depends on execution, developer adoption, enterprise trust, and — crucially — whether the agent-first computing paradigm actually delivers on the productivity promises that underpin all of these announcements. Those answers will come over the next 12 to 24 months. For now, Build 2026 has made Microsoft's position in the AI era clearer than it has ever been.
